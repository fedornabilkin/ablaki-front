# Корень тестового frontend

## Цель и контекст

По просьбе владельца публиковать тестовую сборку непосредственно в
`/var/code/ablaki-front`, аналогично production `/var/www/ablakin.ru`.
Релизы остаются в `/opt/ablaki-frontend-test`; адрес frontend — порт 3181.
Прежний checkout необходимо сохранить вне web-root до первой публикации.

## Группа A: Настройка

- [x] A1. Обновить target, серверный скрипт и примеры nginx.
- [x] A2. Остановить публикацию до rsync, если test web-root ещё содержит checkout.
- [x] A3. Обновить соглашение и команды переноса прежнего checkout и настройки прав, включая ссылки в документации backend.

## Группа B: Проверка и публикация

- [x] B1. Проверить выбор путей, запрет старого пути и сохранность checkout до файловых операций.
- [x] B2. Выполнить deployment tests, Bash syntax, unit tests и build.
- [x] B3. Подготовить проверенные изменения для master и необходимые действия на VPS.

## Критерии готовности

Test workflow и nginx используют один корень `/var/code/ablaki-front`.
При оставшемся checkout скрипт завершается до публикации и удаления файлов.
Production target и backend runtime сохраняются. Применение nginx и ручной test
workflow на VPS проверяются отдельно: прямого SSH-доступа в этой сессии нет.

## Проверки

45 deployment checks и 72 unit tests прошли. Bash syntax и production build
успешны; сборка сохраняет прежнее предупреждение Vite о чанке больше 500 kB.
Защита проверена исполнением серверного скрипта во временных каталогах с `.git`
(файл и каталог), `project` и `package.json`: файлы сохранены, releases не создаётся.
Unit/build выполнены вне Windows-песочницы после отказа esbuild в доступе к
родительскому каталогу; код приложения для этого не менялся.
