# Оптимизация фронтенд-тестов

Цель: актуальные проверки без повторов, измеримое сокращение обычного прогона и отдельная группа slow, обязательная при полном прогоне.

## Группа A: Аудит и замер

- [x] A1. Сохранить исходные результаты и время по файлам/сценариям на одной машине.
- [x] A2. Сверить тесты с текущими компонентами, найти устаревшие проверки и перекрывающееся покрытие.

## Группа B: Изменения

- [x] B1. Удалить неактуальные утверждения, объединить допустимые повторяющиеся проверки и сократить подготовку.
- [x] B2. Отметить измеренно медленные сценарии slow и разделить обычный, slow и полный запуск.
- [x] B3. Согласовать CI: короткий test-gate сохраняется, полный набор включает slow и обязателен перед production.

## Группа C: Проверка результата

- [x] C1. Проверить обычный/slow/полный набор, отсутствие потери обязательного покрытия и сборку.
- [x] C2. Сравнить время до/после, записать команды, результаты и ограничения измерения.

Готовность: обычный запуск исключает slow, полный выполняет обе группы; экономия подтверждена замерами, полезные проверки прав, денег, повторов, гонок и сессий сохранены.

Выполнено локально 30 октября 2026 года. 323 обычных + 121 slow = 444 passed; полный набор проверен также с перемешанным порядком. Сборка и 49 проверок выкладки прошли. Исходный полный прогон занимал 45,17 с; новый после очистки кеша — 21,78 с. [Подробности и команды](../../operations/frontend-tests-2026-10-30.md). Удалённая публикация в эту задачу не входит.
