## Контекст

UI уже мигрирован на **Naive UI** (см. `migrate-to-naive-ui.md`). Цвета сейчас разбросаны по трём уровням:

- **Тема Naive UI** — `themeOverrides` у `<n-config-provider>` в `src/App.vue` (сейчас `primaryColor: '#33a004'` — зелёный, светлая базовая тема).
- **Глобальный SCSS** — `src/index.scss`: `#app { background-color: #f4f7f8 }` (светлый фон) + анимации списков. `src/assets/scss/main.scss` и `src/preloadStyles.scss` сейчас пустые.
- **Локальные `<style>` в компонентах** — 33 захардкоженных цвета (hex/rgb) в 6 файлах: `App.vue`, `navbar/NavBar.vue`, `navbar/SideBar.vue`, `PageHeader.vue`, `games/Orel/GameFilter.vue`, `games/Orel/GamesList.vue`. Часть ссылается на «мёртвые» CSS-переменные, оставшиеся от element-plus (`var(--el-color-primary)`, `var(--border-color)`) — они нигде не определены после миграции.

Цель — единая **тёмная чёрно-оранжевая** тема: тёмный фон, оранжевый акцент. Эталон вёрстки и палитры — `frontend/mockup/black-orange.html`.

## Принципы

- **Mobile-first (важно).** Макет проектируется от мобильного экрана: базовые стили (вне медиа-запросов) описывают узкий экран, расширения для планшета/десктопа добавляются только через `@media (min-width: …)`. Запрещены `max-width`-медиа-запросы как основа вёрстки (как в текущем `NavBar.vue`, где `@include media-breakpoint-down(sm)` прячет элементы — это переписать на min-width-подход). Контрольные точки: база (мобайл), `≥768px` (планшет), `≥1024px` (десктоп). Все интерактивные элементы — с тач-целью ≥44px. Эталон — `frontend/mockup/black-orange.html`.
- **Размеры — в `rem`.** Все размеры (отступы, шрифты, ширины/высоты, радиусы, контрольные точки медиа-запросов) задаются в `rem` (база 16px: `1rem = 16px`), а не в `px`. Исключение — `0` и при необходимости hairline-границы. Это даёт масштабируемость от системного размера шрифта. При перекраске компонентов попутно переводить найденные `px` в `rem`.
- **Максимально использовать Naive UI.** Готовые сущности брать из Naive UI, а не верстать руками: модалки/подтверждения — `n-modal` / `useDialog()`, тосты — `useMessage()`, нотификации — `useNotification()`, плюс `n-button`, `n-input`, `n-form`, `n-card`, `n-data-table`, `n-grid`/`n-space`, `n-layout`/`n-layout-header`/`n-layout-sider`, `n-menu`. Свой CSS — только там, где в Naive UI нет подходящего компонента.
- **Единый источник цвета** — палитра объявляется один раз как CSS-переменные в `:root` (пункт `б.1`) и переиспользуется везде через `var(--…)`. Захардкоженные hex в компонентах заменяются на переменные, а не на новые литералы.
- Naive-компоненты красятся **через тему** (`darkTheme` + `themeOverrides`), а не локальным CSS. Локальный CSS — только для собственной вёрстки (navbar, header, карточки).
- **Иконки — только Font Awesome.** Единственный источник — `@fortawesome/free-solid-svg-icons` через `<font-awesome-icon :icon="..."/>`; регистрация в массиве `myIcons` в `src/fontawesome.js`. Эмодзи и любые другие наборы (`@vicons/*`, `@element-plus/icons-vue`) не использовать. В мокапе иконки подключены через CDN Font Awesome 6 (`<i class="fa-solid fa-…">`) — это визуальный эквивалент; при переносе в код использовать `<font-awesome-icon>`. Иконки из мокапа, которых ещё нет в `myIcons`, добавить туда: `faFire` (лого), `faBars` (бургер), `faDice` (игры), `faBomb` (сапёр), `faDiceFive` (пятёрка). Уже зарегистрированы и переиспользуются: `faCoins`, `faCrosshairs`, `faComments`, `faExchangeAlt`, `faUser`, `faPlus`, `faArrowRight`, `faCheck`, `faBan`.
- Пункты `б.1`–`б.3` — фундамент, выполняются по порядку первыми. Пункты `б.4`–`б.9` (по одному файлу) **атомарны и независимы**, выполняются в любом порядке: пока компонент не перекрашен, он просто остаётся со старыми цветами на тёмном фоне (может выглядеть контрастно, но не ломается).
- Проверка после каждого пункта: открыть соответствующую страницу на `http://localhost:5173` и убедиться, что фон тёмный, акценты оранжевые, текст читаем (достаточный контраст).

- **Размеры в rem:** в новых/изменённых `<style>` нет `px` в размерах (кроме `0` и hairline-границ).
