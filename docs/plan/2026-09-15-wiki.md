# Wiki: аудит и план реализации

Источник задачи №142: http://94.250.251.94:3181/forum/read/64.
Изучены `test/app/controllers/controller_wiki.php`, `models/model_wiki.php`, `config/wiki.php` и шаблоны раздела. Эта задача запрашивает план раздела и реализацию паттернов меню; полноценный CRUD Wiki — следующие этапы плана.

Старый раздел: дерево `wiki_categories(id,name,parent)`, статьи `wiki_pages`, категории, чтение, создание, редактирование, скрытие, копии изменений (`pid`), отметка прочтения и награда рейтингом. Порог создания — 10 рейтинга, редактирования — 5. Содержимое использует BBCode.

Найденные проблемы: действия catedit/hide не имеют явного ограничения администратора в config; редактирование принимает массовый POST без явного списка разрешённых полей; изменение статьи и запись копии раздельны; нет контроля параллельных редакций; повторное начисление рейтинга возможно между чтением и записью; дерево не защищено от циклов и отсутствующих родителей; скрытые страницы и копии требуют единой политики доступа; счётчик авторов включает копии/скрытые статьи; надо проверить HTML-очистку BBCode, CSRF и POST-only для изменений.

## Группа A: Архитектура дерева (в этой задаче)
- [x] A1. Реализовать компоновщик `WikiCategory`/`WikiArticle` с общим `WikiNode`, неизменяемыми дочерними узлами.
- [x] A2. Реализовать посетителей меню и хлебных крошек, рекурсивный Vue-компонент с настоящими ссылками, details/summary для клавиатуры.
- [x] A3. Проверять циклы, глубину, отсутствующих родителей/категории и дубли; добавить поведенческие тесты.

## Группа B: Read-only API и перенос данных
- [ ] B1. Инвентаризировать реальные старые таблицы, кодировки, скрытые/осиротевшие записи и резервную копию перед переносом. Не угадывать подключение и не менять исходные данные.
- [ ] B2. Добавить категории и статьи с публичными whitelist-полями, серверным поиском/пагинацией, единой политикой скрытия и автором PublicProfile.
- [ ] B3. Подключить WikiMenu к API, страницы `/wiki`, `/wiki/cat/:id`, `/wiki/read/:id`, хлебные крошки, пустое состояние и повтор запроса.
- [ ] B4. Отображать BBCode через разрешённый набор элементов с очисткой URL/HTML; тестировать XSS.

## Группа C: Авторство и модерация
- [ ] C1. Явные права: посетитель читает опубликованное, участник создаёт/редактирует по серверному порогу, модератор управляет категориями и скрытием.
- [ ] C2. Сохранять редакцию и неизменяемую предыдущую версию атомарно; optimistic lock предотвращает потерю чужой редакции.
- [ ] C3. Применить циклозащиту также на сервере при переносе категории, запретить удаление непустой категории без явной операции переноса.
- [ ] C4. Награда один раз на редакцию, блокировка записи, транзакция рейтинга/истории/награды и защита повторов.

## Группа D: Готовность раздела
- [ ] D1. Проверить права, скрытие, поиск, пагинацию, прямые ссылки, навигацию назад, циклы, XSS, конфликты редакций и конкурирующие награды в MySQL/PostgreSQL.
- [ ] D2. Проверить мобильное дерево, клавиатуру и длинные заголовки; выложить в test после миграции на копии данных.

Критерий полного раздела: чтение/редактирование/история/модерация и награды работают по единому API, данные перенесены без потери, исходные уязвимости не перенесены. Реализованные сейчас паттерны не означают готовность всего Wiki.
