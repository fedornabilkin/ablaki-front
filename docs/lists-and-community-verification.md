# Проверка списков и функций сообщества

Дата: 2026-09-05. Реализация работает непосредственно в master. Общие элементы подключены к действующим страницам участников, форума, истории, переводов, биржи, рефералов, статистики и двух игр, а также к спискам на главной и в модальных окнах.

## Автоматические проверки

- Vitest: 72 проверки в 11 файлах прошли.
- Production-сборка Vite прошла. Предупреждение о размере общего UI-чанка остаётся; отдельного TypeScript typecheck в проекте нет.
- Backend: совокупно 139 проверок в шести изолированных SQLite suites и lint 34 PHP-файлов. Они выполнены с установленным Yii 2.0.47; при финальной синхронизации включён уже влитый владельцем lock с Yii 2.0.49.4, требующий установки зависимостей и повторной проверки до серверного выпуска. Подробности — в `back/docs/frontend-api-integration-audit.md` соседнего backend-репозитория.

## Проверка браузером

Использованы только локальный frontend `localhost:5174` и отдельный fixture API `127.0.0.1:4178`. Fixture хранит данные в памяти и не обращается к действующему API. В production не отправлялись игровые ходы, подарки или награды.

- Список участников: переход на страницу 2 записывает `page=2`; поиск на сервере восстанавливает первую страницу и показывает отфильтрованное количество. Параметр `q` остаётся в URL.
- Статистика: выбор периода обновляет `period`, рейтинг и URL. Перезагрузка восстанавливает период; переход назад возвращает предыдущую страницу с её поиском.
- Онлайн: список содержит ссылки на стены, общее количество и страницы. Поиск `online_q` сохраняется независимо от поиска основной страницы.
- Мобильная шапка: фактическая ширина контента 360 CSS px; горизонтального переполнения нет. При прокрутке шапка остаётся на `top=0`, высота сокращается примерно с 189 до 149 px. В модальном окне ширина 375 px и также нет переполнения.
- Ежедневная награда: успешный ответ обновляет счёт с сервера; повтор сообщает, что награда уже получена, без повторного начисления.
- Игры: кон восстанавливается из URL, недоступная страница ограничивается ответом API. Показаны статистика за сегодня, количество и сумма собственных игр, последние игры с игроками, датой, временем и короной победителя.
- Форум: подтверждённая передача 1 Cr обновляет счёт, отметку отправителя и количество благодарностей. В списке передавших есть новый отправитель, ссылки на стены и работающая пагинация.
- История баланса: выбор типа меняет `type` в URL и серверный результат; пустой результат отображается корректно.

Локальный fixture проверяет взаимодействие компонентов, но не доказывает готовность production API, CORS, миграций или блокировок PostgreSQL/MySQL.

## Порядок выпуска

1. На копии целевой БД проверить новые миграции и конкурентные операции; сохранить резервную копию перед серверными изменениями.
2. Применить `m260905_120000_create_forum_comment_gift_table` и `m260905_180000_create_user_presence_table` перед включением нового кода API. Список уже применённых и ожидающих миграций сверить на конкретном сервере.
3. Обновить backend. Проверить общий envelope списков, авторизованные маршруты и CORS отдельного API-хоста.
4. Отправить frontend master: действующий GitHub Actions автоматически соберёт и опубликует фронтенд. Затем проверить версию деплоя, загрузку страниц и запросы к API.

Серверный шаг требует расположения backend и способа его обновления. Отправка кода в GitHub сама по себе не подтверждает обновление API. Старые блокеры экономики, описанные в планах backend, этим изменением не закрываются.
