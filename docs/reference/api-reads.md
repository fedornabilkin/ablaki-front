# Запросы SPA и общие ответы API

Обновлено 2026-10-31. Полный [контракт объединённых чтений](../../../back/docs/architecture/api-consolidation.md), [карта всех вызовов и маршрутов](../../../back/docs/architecture/api-route-map-2026-10-31.md), [отчёт проверки](../../../back/docs/operations/api-audit-2026-10-31.md).

Для чтений используем `readApi` из `services/httpClient.ts`. Оно объединяет только незавершённые запросы с одинаковыми адресом, параметрами и сессией. После получения ответа новое чтение идёт на сервер; долговременного кеша нет. `AbortSignal` оставляет отмену у конкретного потребителя. Каждый компонент получает собственный JSON. POST/PUT/PATCH/DELETE отделяют поколения чтений на отправке и завершении, в том числе при ошибке. Токены остаются у auth-store, запоздалые ответы отсекает владелец состояния страницы.

История использует `community.loadHistory()` вместо отдельной загрузки списка и типов. Страница персонажа использует `worldCharacter.loadCharacterOverview()` вместо отдельных economy/progression/active-build; поповер навыков продолжает лениво запрашивать только progression. Старые адаптеры остаются для совместимости, но новые страницы не должны дублировать загрузку managed-компонента.

Ежедневные награды и запуск сапёра отправляются POST. Их прежние GET-адреса изменяют состояние, поэтому запрещены для `readApi` и предзагрузки. Preview и подтверждение покупки остаются разными командами.

Добавляя чтение экрана, сначала проверьте существующие `view=home`, `include=tree`, `include=character`, `include=types`. Объединяйте только совместно используемые данные с одинаковыми правами; проверяйте версию и вложенную структуру неизвестного JSON. Список имеет `items`, `_meta`, `_links`, отсутствующая сущность — `null`.

Порядок выкладки: backend, затем frontend. Новый SPA требует поддержки новых include/POST; откат только frontend совместим с новым API. Миграций БД в этом пакете нет.
