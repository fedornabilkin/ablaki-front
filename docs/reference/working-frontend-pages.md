# Рабочие страницы и действующий API

Дата проверки: 2026-09-05. Ветка: `feat/frontend-pages`.

## Страницы
- Главная и каталог игр: публичные переходы, темы форума и новые участники из API.
- Форум: все/мои темы, чтение, создание темы с первым сообщением, ответы, страницы списка.
- Участники, публичная стена, редактирование своей стены, профиль с реальным счётом и ежедневными наградами.
- Орлянка: список, создание, участие, свои игры, отмена, история.
- Сапёр: доступные игры, создание и прохождение поля. Известные ограничения ниже.
- Биржа: существующие списки, история и действия; исправлены создание, обновление списка и индикация загрузки.
- История баланса/кредитов и рейтинга; создание, получение, отмена и история переводов.

## Контракты
Все запросы проходят через `services/httpClient.ts`; адрес API по-прежнему задаёт `VITE_API_URL`. Авторизация принадлежит Vuex. Публичные страницы не требуют входа, личные маршруты используют существующий guard с возвратом после входа.

| Раздел | Методы |
| --- | --- |
| Форум | GET/POST v1/forum-theme; GET v1/forum-theme/my и /:id; GET/POST v1/forum-comment |
| Участники | GET v1/users/last, v1/users/wall/:login, v1/users/profile; PATCH v1/users/wall |
| История | GET v1/history/balance, v1/history/rating |
| Переводы | GET/POST v1/transfer; GET v1/transfer/history; PUT/DELETE v1/transfer/:id |
| Орлянка | GET/POST v1/orel; GET /my и /history; POST /play/:id; DELETE /:id |
| Сапёр | GET/POST v1/saper; GET /start/:id; POST /play/:id |
| Награды | GET v1/bonus/everyday и v1/rating/everyday — только по нажатию, это команды |

Создание темы не принимает первое сообщение: frontend выполняет второй POST комментария. Если он отклонён, ID созданной темы сохраняется и повторная попытка не создаёт вторую тему. Ответы с ошибками в HTTP 200 проверяются; пустой ответ 201/204 у команд допускается. Заголовки пагинации могут отсутствовать из-за CORS: в таком случае используются кнопки предыдущей/следующей страницы без выдуманного общего количества.

## Подтверждённые ограничения API
- На проверенном сервере GET v1/stat, v1/stat/top, v1/duel, v1/five возвращают 404. Для этих разделов не показываются демонстрационные данные. Старые исходники сохранены.
- GET v1/saper/my и v1/saper/history возвращают 404. В backend включён strict parsing; методы контроллера без правил URL недоступны. Старые ссылки перенаправлены на доступные страницы.
- Сапёр не возвращает состояние поля и не предоставляет чтение активной игры. Уход со страницы во время игры сопровождается предупреждением; неподтверждённый ход блокирует дальнейшие действия. HTTP 400 с сообщением «Игра проиграна»/«Game lost» считается подтверждённым проигрышем, сетевой сбой — нет. Для восстановления после перезагрузки нужны изменения backend.
- В сериализации перевода отсутствует сумма; frontend показывает её только когда сервер действительно передаёт поле. Существующий PUT получает перевод по ID; пароль этим действием не проверяется. Доработка прав и контракта переводов относится к backend.
- PATCH стены и авторизованные операции реализованы по PHP-контрактам и проверены на локальном тестовом сервере. Их работоспособность именно в production-аккаунте пока не подтверждена.
- GET-проверка без токена возвращает 401 для орлянки, сапёра, биржи, переводов и истории. Это проверка доступности защищённых маршрутов, не подтверждение успешной операции.

## Цвета и адаптивность
Единый источник палитры — `project/src/theme/tokens.ts`: CSS-переменные и тема Naive UI получают одни значения. Сохранена тёмная чёрно-оранжевая гамма, включена русская локаль Naive UI. Мобильная компоновка одноколоночная, навигация открывается в боковом меню; крупные экраны получают сетку. Неиспользуемые семейства иконок исключены из сборки.

## Проверки
- Unit-тесты: API-ответы, пагинация без заголовков, пустые 201/204, отложенные ответы при смене темы, завершение загрузки после ошибки, публичные и закрытые маршруты, существующая авторизация.
- Браузер с действующим API: чтение форума и темы; главная с загрузкой обсуждений и участников.
- Браузер с локальными ответами: вход с возвратом, создание темы с отказом первого комментария и успешным повтором, результат орлянки, разрешённые ряды и проигрыш сапёра, перевод с пустым 201, профиль, редактирование стены, закрытие мобильного меню.
- На фактической ширине 360 CSS px у проверенных страниц нет горизонтального переполнения. Отдельные таблицы биржи прокручиваются внутри своего блока.
- Сборка предупреждает о крупном общем пакете Naive UI. Отдельного typecheck в проекте пока нет.
- Production-данные, backend и VPS не менялись.

## Повтор локальных сценариев
Из `project` запустить `node tests/fixtures/portal-server.mjs`. В другом терминале установить VITE_API_URL=http://127.0.0.1:4178/ только для текущего процесса и запустить Vite на порту 5174. Тестовый сервер не пересылает запросы в production и возвращает пользователя preview на локальный запрос входа. Он хранит данные в памяти и намеренно отклоняет первый комментарий. Не использовать этот адрес в переменных GitHub или production.
