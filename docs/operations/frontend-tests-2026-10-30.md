# Проверки frontend: обычный, slow и полный прогон

Обновлено 30 октября 2026 года. Изменения локальные: тесты, конфигурация Vitest, документация и команды CI. Код приложения и удалённые окружения этим пакетом не изменяются.

## Команды

Выполнять из `project`:

| Команда | Состав |
| --- | --- |
| `npm run test:unit` | 323 проверки в 45 файлах: контракты, расчёты, права, сессии, повторные команды, ошибки и фоновые запросы. |
| `npm run test:slow` | 125 проверок в 4 файлах после мобильного пакета и поповеров: тяжёлые сценарии рендеринга и взаимодействий. |
| `npm run test:full` | Все 448 проверок: сначала unit, затем отдельный проект slow в том же процессе Vitest. |
| `npm run test:profile` | Полный набор с отчётом о стоимости импортов. |

Выбор файлов сохраняется: `npm run test:unit -- tests/auth.test.ts tests/httpClient.test.ts` или `npm run test:slow -- world-controls-interaction`.

## Что актуализировано

Шесть небольших файлов объединены с соответствующими наборами: координаты и проекция прогресса — с прямыми действиями мира; пищевые контракты — с MVP; архивирование дерева — с раскладкой нод; камера крафта — с классическим крафтом; прокрутка — с маршрутизацией. Сценарии сохранены. Проверки предметных данных истории игр отделены от рендеринга.

Удалены повторная проверка авторизации истории игр и устаревшие утверждения о строковом суффиксе `Cr` у неиспользуемого форматтера. Проверки дефицита личного пополнения сохранены, отображение монет проверяется в компонентах. Общая матрица доступа расширена на 11 маршрутов персонажа, хранилищ, экипировки, восстановления и игр.

Обновлены фикстуры мини-склада (5 ячеек), восстановления здоровья от еды, обязательных имён нод и revision. Тест рецепта проверяет текущую ссылку на изготовление выбранной стоянки. Проверка большого инвентаря явно требует доступности всех 100 слотов. Общий компилятор клиентских шаблонов переиспользуется; устранены предупреждения Vue о пустых шаблонах и отсутствующих props без подавления консоли.

В тесте маршрутов вместо полного графа `WorldPage` загружается заглушка экрана: реальные маршруты, lazy import и ограничения доступа проверяются. В проверках `setup` переводов и быстрых игр подменены неиспользуемые дочерние UI-компоненты. Файлы с разными API-моками сохранены раздельно.

## Как определён slow

Учитывалась подготовка файла, импорты и рендеринг: отдельные тела тестов короткие, но загрузка Vue/Naive UI и компиляция шаблонов занимают секунды. Самый долгий исходный отдельный сценарий занимал 234 мс; проверка 100 слотов — 222 мс. Поэтому разделение только по времени тела теста не устраняло бы основную задержку.

| Файл slow | Проверки |
| --- | --- |
| `world-controls-interaction.slow.test.ts` | 105: широкий набор клиентских шаблонов и взаимодействий мира. |
| `craftView.slow.test.ts` | 6: рендеринг рецептов и большого инвентаря. |
| `gameHistory.slow.test.ts` | 7: таблицы истории, аватары, иконки и управление FiveBoard. |
| `communityLists.slow.test.ts` | 3: рендеринг списков сообщества. |

Каждый такой файл имеет суффикс `*.slow.test.ts` и маркер Vitest `// @module-tag slow`. Обычный проект исключает эти файлы до загрузки модулей. При добавлении медленного файла использовать оба обозначения. Финансовые расчёты, права, обработка повторов, смена сессии и бюджеты фоновых запросов остаются в обычном наборе.

## Производительность

Замеры сделаны последовательно на одной локальной машине: Windows, Node.js 22.18.0, Vitest 5.0.0, 8 доступных процессоров, 8 ГБ RAM. CI использует Node.js 24/Linux; его время отдельно не измерялось. Значения Vitest включают запуск воркеров, трансформацию, импорты и сами тесты; полное время npm измерено внешним таймером.

| Набор | Тесты / файлы | Время Vitest |
| --- | --- | --- |
| Исходный полный, стандартные forks | 434 / 55 | 45,17 с |
| Тот же исходный набор, изолированные threads, 4 воркера | 434 / 55 | 21,77 с |
| Новый полный, после `vitest --clearCache` | 444 / 49 | 21,78 с |
| Новый обычный, медиана трёх повторов | 323 / 45 | 9,50 с |
| Новый slow, повторный запуск | 121 / 4 | 6,53 с |
| Новый полный, повторный запуск | 444 / 49 | 15,45 с |

Новый полный запуск после очистки кеша занял 23,13 с от старта npm до завершения. Обычные повторы: 9,53 / 9,50 / 8,27 с Vitest, 10,74 / 10,78 / 9,49 с целиком. На время влияет нагрузка ОС; это локальные измерения, а не гарантия длительности CI или выкладки.

Повторный полный запуск занял 16,77 с целиком, отдельный slow — 7,68 с. Полный набор с перемешанным порядком прошёл за 14,80 с Vitest / 16,01 с целиком. Относительно исходного полного набора время Vitest уменьшилось на 66% с локальным кешем и на 52% после его очистки. В итоговых запусках предупреждений Vue нет.

Используются максимум 4 воркера и не больше доступных процессоров. Изоляция файлов включена. Трансформированные модули сохраняются в `node_modules/.vitest-cache`; `npm ci` удаляет этот локальный кеш. Отдельный сетевой кеш для него в CI не добавлялся.

## Проверки и CI

Сверены JSON-отчёты: множества файлов unit и slow не пересекаются, их объединение и набор тестов точно совпадают с полным прогоном. Все 444 проверки прошли также с перемешанным порядком (`--sequence.shuffle --sequence.seed=731`), без skipped/todo.

`npm run build` прошёл; предупреждение о размере крупных chunks существовало до этой задачи. Проверки скриптов выкладки: 49 passed. Обязательный короткий набор авторизации/HTTP: 13 passed.

Перед test остаются обязательными авторизация, HTTP-клиент, проверки выкладки и сборка. После публикации test отдельный CI job выполняет `test:full`. Перед production полный `test:full` обязателен до сборки и публикации. Таким образом, переименование обычного запуска не исключает slow из обязательной полной проверки.

Завершённый [план работ](../plan/done/2026-10-30-frontend-test-optimization.md). Логи, исходные и итоговые JSON-отчёты сохранены вне Git в `temp/frontend-tests-artifacts` общей рабочей папки.

Локальный frontend `cb38e2a`: `npm run test:full` завершился успешно — 444 теста в 49 файлах, 28,65 с по Vitest. `npm run build` прошёл на установленном Vite 7.3.6 за 24,17 с. Эти значения относятся к отдельному запуску и не заменяют сравнительные замеры оптимизации выше.

Отдельного typecheck в package scripts и просмотренном CI нет. Ручная браузерная приёмка и удалённая публикация в эту проверку не входили.
