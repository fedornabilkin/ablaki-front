# Архитектурное соглашение frontend

Адаптировано из PCM Helper с сохранением текущей структуры Ablaki.

## Границы и ответственность
- Сохранять домены user, games, forum, exchange, chat, craft, city. Общий транспорт находится в services, доменные сущности — в entities.
- UI зависит от прикладных сервисов и доменных контрактов. Общие транспортные функции не импортируют страницы и store.
- Компонент отвечает за отображение и пользовательские события; вычисления и бизнес-правила размещаются в доменном слое.
- Entity хранит состояние и поведение сущности, builder преобразует DTO, service координирует сценарий.
- Не добавлять builder или класс для механического оборачивания простого ответа.
- Размер файла — повод для анализа ответственности, не формальный повод дробить код.
- Следовать SOLID/GRASP; применять композицию и паттерны только когда они упрощают решение.

## Новый код
- Новая логика — .ts, новый Vue UI — script setup lang="ts" и template lang="pug".
- Props/emits типизировать; входные props и вложенные объекты не изменять.
- Неизвестные данные проверять как unknown. Приведение типа не заменяет runtime-валидацию.
- Общие типы переиспользовать. DTO внешнего API отделять от внутреннего формата.
- Алиас @ использовать от src, относительные импорты — внутри локального модуля.
- Чистые преобразования оформлять функциями; классы оправданы состоянием, инвариантами или зависимостями.

## Состояние и асинхронность
- Auth-store является единственным владельцем пользовательской сессии. HTTP-клиент получает токен через настройку в main.
- Доступ к API выполнять через services/httpClient.ts; глобальные axios.defaults для авторизации не использовать.
- Guard ждёт восстановления сессии. Наличие строки токена не означает подтверждённую авторизацию.
- Запоздалый ответ старой сессии не должен менять новый аккаунт.
- Promise должен иметь обработку результата и ошибки; loading завершается и при отказе.
- Устаревшие ответы игнорировать или отменять. Повторное нажатие не запускает дублирующую команду.
- Локальное состояние оставлять локальным; timers, подписки и соединения освобождать при завершении владельца.
- Клиентская блокировка не заменяет серверные права и транзакции.

## Ошибки и демо
- Ошибки ввода, транспорта и сервера различать; сырые исключения не показывать пользователю.
- Сохранение и импорт применять только после успешной проверки данных.
- Демонстрационные адаптеры должны быть явно включены и изолированы от реальной экономики.
- Полная миграция Vuex, TypeScript и структуры каталогов не является обязательным условием точечного исправления.
