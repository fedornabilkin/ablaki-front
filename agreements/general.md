# Общие соглашения frontend

Адаптировано 2026-09-05 из соглашений PCM Helper. Документ самодостаточен; соседний репозиторий для разработки не требуется.

## Подход к изменениям
- Перед изменением изучать модуль, аналогичные решения и всех потребителей затронутого контракта.
- Ограничивать изменение задачей; сохранять пользовательскую работу. Не проводить массовую смену стиля или структуры.
- Предпочитать понятный код, существующие компоненты и зависимости. Не вводить абстракции под гипотетические требования.
- Новые зависимости должны решать конкретную задачу; package.json и package-lock.json изменяются согласованно.
- Эти правила распространяются на разработчиков и AI-агентов.

## Структура и стек
- Этот Git-репозиторий — frontend; приложение находится в project, исходники — project/src.
- Vue 3, Vite, Vue Router, Naive UI, Pug, SCSS, Font Awesome. Vuex auth пока является владельцем сессии; Pinia используется в новых доменах.
- Сохранять Naive UI и существующую тему. Не переносить Bulma, D3, PCM-цвета и AI-адаптеры из PCM Helper.
- Новые планы размещать в plans согласно [plans.md](plans.md). Существующие docs/plan сохранять.
- Правила нового кода: [architecture.md](architecture.md). Целевая схема публикации: [deployment.md](deployment.md).

## Проверки
- Из project запускать npm run test:unit и npm run build после значимых изменений.
- test:unit использует Vitest. Не ссылаться на отсутствующие lint, typecheck или test:e2e:heavy.
- Новый код с логикой создавать на TypeScript, новые Vue-компоненты — script setup lang="ts". Старый JS переводить только при необходимости задачи.
- Отдельный typecheck ещё не настроен; транспиляция Vite/Vitest не заменяет проверку типов.
- Для документации достаточно проверить содержание, ссылки и diff.
- Проверять конкурирующие запросы, сбои API, загрузку, пустые данные и сохранность состояния.
- Завершённые проверки, их ограничения и ранее существовавшие ошибки сообщать отдельно. Сборка не подтверждает production-деплой.

## Данные и интерфейс
- Входной JSON и localStorage считать недоверенными; использовать проверку структуры и безопасный парсер.
- Пользовательские данные и баланс не должны зависеть от демонстрационного состояния.
- Секреты не включать в VITE_*; эти значения публичны.
- Иконки брать из Font Awesome; новые UI-библиотеки требуют отдельного архитектурного решения.
- Тексты и документация — UTF-8; технические детали и токены не выводить пользователю.
